# 【中秋国庆 VibeCoding】省脚力路线卡（EasyWalk Route Card）—— 带爸妈出游不走断腿的假期步行安排神器

参与话题：#中秋国庆 VibeCoding

## 一句话介绍

把选好的景点整理成**大字版、可调整、能导出图片**的步行路线卡：今天去哪、每个路段走多久、最长连续走多久、在哪歇脚，一眼看清；导出 PNG 直接发家庭群，老人小孩都看得懂。

灵感来自真实场景（非评论区认领）：双节假期想带爸妈逛园子、走老街，老人走不了太久，行程得按“省脚力”来排。

## 它解决了什么假期问题

1. **行程怎么排不累**：逐段填写/自动获取步行时间，实时统计「总步行 / 全程 / 最长连续步行」；哪段数据缺失就只报“已知下界 + 待补充项”，绝不把没算完的数当成完整总量糊弄人。
2. **在哪歇脚心里有数**：站内检索附近厕所 / 歇脚处，候选一键转成路线上的休息点，还会告诉你“绕行歇脚比直达多走约 X 分钟”；直线距离只标注“直线距离，非步行路程”，不参与任何计算。
3. **导出就能发家庭群**：大字路线卡固定 360px 逻辑宽度、自动分页、3 倍像素密度导出 PNG，不裁切不缩字号；预览和导出用同一份视图模型，所见即所得。已采纳的路段时间可离线查看。
4. **双节氛围拉满**：9/20–10/7 节令窗口内界面自动叠加节庆动画（明月月晕、星斗、桂瓣、旗串、国旗、烟花），同日同景、隔日更新；导出成功还有烟花庆祝。纯视觉覆盖层，不影响操作、不进导出画面，尊重系统“减少动态效果”设置。
5. **零门槛、零隐私顾虑**：无账号无云端，行程全部存在本机浏览器（localStorage）；图片导出在本机完成，不上传行程截图。

## 用 TraeCode 创作的过程

一开始只是把真实需求原封不动丢给 TraeCode（SOLO 模式），连“最好大字报照顾老花眼”这种细节都写上：

![TraeCode 过程截图 1：需求输入与 Agent 拆解](docs/发帖素材/trae-1-需求输入与Agent拆解.png)

TraeCode 先读项目现状，把需求整理成《需求说明书》《详细设计说明书》，并把容易翻车的口径提前定死（缺失数据只报下界、A→B 与 B→A 是两条路段时间、地图估算显式采纳才落盘、导出规格 360/960/3x……），再给出分层落地方案：

![TraeCode 过程截图 2：方案与关键口径](docs/发帖素材/trae-2-Agent方案与关键口径.png)

关键步骤：

1. **先定口径再写码**：需求/设计两份说明书先行，前后端共享 Zod 契约（`shared/contracts/`），避免各写一份类型。
2. **分层实现**：纯领域计算（`src/domain/`，缺失下界、连续步行、状态合成）→ Web Worker 有界规划搜索（`src/workers/`）→ 功能 UI（行程/设施/规划/大字卡/导出）→ Fastify 高德适配层（Key 只在服务端，响应与日志不含凭据）。
3. **测试兜底**：TypeScript strict + 279 项单测（领域/组件/服务端契约/Worker）+ 22 项 Playwright e2e（桌面 + 移动双视口）；真实核验过“JS API 平台 Key 与 Web 服务平台 Key 不可混用”这个坑。
4. **双节彩蛋**：按活动主题补了节庆动画覆盖层，种子化生成、同日同景、隔日更新。
5. **一键上云**：用 IGA Pages 部署在线演示，`api/` 目录直接映射 Pages Functions，本地 Fastify 与线上函数共用同一份业务核心（`server/api-core.ts`）。

## 技术栈

React 18 + TypeScript（strict）+ Vite｜Web Worker 规划搜索｜Fastify + 高德 Web 服务适配层（本地）/ IGA Pages Functions（线上）｜html-to-image 本机导出｜localStorage 持久化｜279 单测 + 22 e2e。

这个双节，不管是回家团圆还是出门旅行，希望这张“省脚力路线卡”能帮你把假期的路排得更轻松一点。欢迎试玩反馈！
